這份實作要你做什麼

你會在自己的 GitHub 上做出一個網站，用手機在戶外走一次真實的 GPS 紀錄，再用 VS Code 和 Copilot 分析自己的數據。完成後你會交出三樣東西：你的網址、一份軌跡檔、一份實作紀錄表。

任務 1　用範本建立你的倉庫

  1. 開啟老師的範本：https://github.com/RichTsai1688/pace-site。
  2. 按綠色的 Use this template，選 Create a new repository。
  3. Owner 選你自己的帳號。Repository name 填 pace-你的名字（英文或拼音，不要有空白）。選 Public，按 Create repository。
你的倉庫裡有 index.html、README.md、.gitignore 與 .github 資料夾。

交件：你的倉庫網址（格式：https://github.com/你的帳號/pace-你的名字）。

任務 2　開啟 GitHub Pages

  1. 在你的倉庫按 Settings，左側選 Pages。
  2. Build and deployment 的 Source 選 Deploy from a branch。Branch 選 main，資料夾選 / (root)，按 Save。
  3. 等 1 到 3 分鐘，頁面上方會出現網址：https://你的帳號.github.io/pace-你的名字/。

免費的 GitHub Pages 需要 Public 倉庫。不確定哪裡要按，可以在 Copilot Chat 的 Ask 模式問：「我要在 GitHub 倉庫開啟 Pages，從 main 分支根目錄發布，請一步一步告訴我要點哪裡。」

用電腦開啟你的網址，網址開頭是 https://，首頁與地圖都出現。

任務 3　用 VS Code 複製到電腦，並在本機預覽

  1. 開啟 VS Code，按 Cmd+Shift+P（Windows 是 Ctrl+Shift+P），輸入 Git: Clone。
  2. 貼上你的倉庫網址，選一個資料夾存放，按 Open。第一次可能要求登入 GitHub，請自己完成登入，不要把密碼或 token 貼進聊天。
  3. 開啟 Copilot Chat（Mac 按 Cmd+Ctrl+I；Windows 按 Ctrl+Alt+I）。模式選 Ask，輸入：
/explain-project
Copilot 用表格列出每個檔案的用途，並說明資料從「開始運動」到「匯入檢視」經過哪些檔案。
  1. 把模式改成 Agent，輸入：
/preview-locally

Copilot 會在終端機啟動伺服器，並告訴你網址。用瀏覽器開 http://localhost:8000，按「開始運動」→「先體驗示範運動」，距離數字會增加。

首頁正常，示範運動的距離會增加。如果 Copilot 無法啟動伺服器，就在終端機手動執行 python3 -m http.server 8000（Windows 是 py -3 -m http.server 8000）。

交件：Copilot 的表格截圖（任選一張）。

任務 4　修改一個地方，推送後讓網站更新

  1. 在 Copilot Chat 切換到 Edit 模式，附加 index.html，輸入：
/change-and-check 把 index.html 側邊欄的 FENG CHIA UNIVERSITY 改成「我的班級名稱」（用你自己的班級名稱）。只改這一處，其他不動。
  1. 在本機重新整理，確認側邊欄已經改了。
  2. 推送：在 Chat 切換到 Agent 模式，輸入 /publish-changes。Copilot 會先列出變更的檔案，確認沒有 my-tracks/ 或 .json、.csv，才會 commit 與 push。

也可以不用 Copilot：左側 Source Control（Ctrl+Shift+G）寫 commit 訊息、按 Commit，再按 Sync Changes。

等 1 到 3 分鐘，重新整理你的 Pages 網址，側邊欄出現新名稱。仍然沒有更新，就強制重新整理一次，再等 2 分鐘。

交件：Pages 網址上看到新名稱的截圖。

任務 5　手機 GPS 實測（核心任務）

這一步一定要在戶外用手機完成。電腦的 localhost 只能測試介面，真實定位要用你的 https 網址。

  1. 用手機開啟你的 Pages 網址。Android 用 Chrome，iPhone 用 Safari。
  2. 允許網站使用定位，並開啟「精確位置」。依手機的提示操作即可。
  3. 到戶外，按「我的定位」，地圖上出現藍點。室內通常無法定位。
  4. 按「開始運動」，填入代號（不要填真實姓名）、身高、體重與年齡，活動選「舒適步行」或「快走」，勾選同意，再按「開始 GPS 運動」。
  5. 在地圖上點一下老師指定的集合點（老師會告訴你地點名稱）。畫面會顯示到集合點的直線距離。
  6. 走 15 到 20 分鐘。網頁必須保持在前景，停下來休息時按「暫停」。
  7. 按「結束並儲存」。到「運動紀錄」，在那一筆紀錄上按「軌跡」下載 JSON，再按「摘要」下載 CSV。
  8. 把兩個檔案傳到電腦（AirDrop、Google Drive，或寄給自己），放進 VS Code 專案的 my-tracks/ 資料夾。沒有這個資料夾就新增一個。
手機上地圖有橘色軌跡、綠色「起」點，運動紀錄列表有一筆 GPS 紀錄（不是示範），總距離至少 0.2 公里，有效點數至少 30 個。
軌跡檔含有你的位置。它只留在你自己的電腦，只交給老師，不要推送到 GitHub，也不要公開分享。.gitignore 已經忽略 my-tracks/ 與 *.track.json。

交件：軌跡 JSON 與摘要 CSV（依老師指示交件，僅限課堂使用）。

任務 6　匯入檢視與 Copilot 分析

A．在網站上看你的路線。在你的 Pages 網址按側邊欄的「匯入檢視」，選擇你的軌跡 JSON。請看：起點（綠色「起」）、終點（藍色「終」）、集合點（橘色「集」）、距離、時間、平均速度、估算熱量，以及熱量算式。

B．讓 Copilot 驗算。在 VS Code 的 Copilot Chat 切換到 Agent 模式。用 #file 附加你的軌跡檔，再輸入：

/analyze-track #file:my-tracks/你的檔名.json
Copilot 算出的總距離與網站顯示的距離，差異小於 0.1%。最大速度不超過 8 m/s。熱量與網站一致。若不一致，請把 Copilot 的回答與數字寫進實作紀錄表，並問它差異的原因。

C．填寫實作紀錄表。開啟課堂發下的《實作紀錄表》，把數字填入，回答分析題。

交件：實作紀錄表（下載 .txt 或列印）。

選做：改一個參數，做對照實驗

這是課後作業。目標是觀察定位門檻如何影響有效點數與距離。

  1. 在 Copilot Chat 的 Edit 模式附加 core.js，輸入：/change-and-check 把 core.js 的精度門檻從 35 改成 20，說明會影響什麼。
  2. 用 /publish-changes 推送，等 Pages 更新。
  3. 在同一條路線再走 15 分鐘，儲存新的軌跡檔。
  4. 把兩次紀錄的有效點數、總距離與段數比較，寫進實作紀錄表的 D 區。
一次只改一件事。比較時，天氣、路線與走路速度要盡量相同，比較才有意義。

附錄 A．進階：路線 B，全端在自己電腦執行

在 VS Code 開啟 campus-move 資料夾。每個 prompt 貼完後讀 Copilot 顯示的指令，按 Continue。

步驟 1：安裝相依套件

@workspace 請先用 Ask 模式讀 README.md 與 package.json，用繁體中文列出執行這個專案前需要哪些工具與版本，以及 install:ci、build、dev、start 四個 npm script 各做什麼。
請用 Agent 模式：先執行 node -v 確認版本是 22.13 以上，然後執行 npm run install:ci。安裝需要幾分鐘，結束後告訴我有沒有 error。若只有 deprecated 警告，可以繼續下一步；出現其他 error 就停下來問老師。

步驟 2：建置並建立本機資料庫

請用 Agent 模式：執行 npm run build。完成後確認 dist/server/wrangler.json 存在。接著執行 README.md「執行」段落裡那行以 node --import ./scripts/sites-env.mjs 開頭的 wrangler d1 execute 指令，對本機 D1 套用 drizzle/0000_last_old_lace.sql。只執行一次。
終端機顯示 SQL 執行成功，.wrangler/state 資料夾出現。

步驟 3：設定教師帳號

專案根目錄的 .dev.vars 寫著 TEACHER_EMAILS="seedy@sites.test"，這是本機模擬登入的帳號，直接沿用即可。這個檔案不可以 commit 或上傳。若資料夾裡沒有這個檔案，在 campus-move 根目錄新增，內容只寫這一行，並執行 git check-ignore .dev.vars 確認它被忽略。

步驟 4：啟動開發伺服器並登入

請用 Agent 模式執行 npm run dev，等它印出網址後告訴我。不要關閉這個終端機。

瀏覽器開 http://localhost:5173/classroom.html，按「使用 ChatGPT 帳號登入」。本機會以模擬帳號 seedy@sites.test 登入，畫面出現 TEACHER WORKSPACE。建立一個班級，拿到 12 碼班級碼，新增一堂課。

本機模擬只有一個身分，所以學生加入與繳交流程用自動測試驗證：

請用 Agent 模式執行 node tests/classroom.mjs，把最後一行輸出貼給我並用繁體中文解釋它驗證了哪些事情。
輸出以 PASS: 開頭，提到 61 人同時加入只收 60 人、60 人同時繳交成功。

步驟 5：型別檢查

請用 Agent 模式執行 npx tsc --noEmit，沒有輸出代表通過。若有錯誤，把錯誤貼給我並解釋。

附錄 B．教師：正式發佈給全班

班級中心依賴 Sites 平台注入的 ChatGPT 登入標頭，所以完整版要透過 ChatGPT Codex 的 Sites 工作流程發佈，不是 GitHub Pages。發佈前後要做的事：

  • 在 Sites 的環境變數設定 TEACHER_EMAILS，填教師 email，逗號分隔。不要寫進 hosting.json 或任何前端檔案。
  • 發佈流程會自動套用 drizzle/ 的 migration，確認 D1 binding 名稱是 DB。
  • 預設網站是擁有者私有。到 Sites 分享設定開放給學生帳號，私人預覽網址不等於全班可用。
  • 用一個學生帳號走完登入、加入、核准、GPS 記錄、繳交、查看；Android 與 iPhone 各測一次。
  • 班級碼只在課堂上公布，不貼公開群組。
